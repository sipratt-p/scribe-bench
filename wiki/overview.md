# Overview

**What was built.** `scribe-bench`: a reproducible harness over open data for the ambient-scribe pipeline (audio → transcript → clinical note → verification), with runners for seven ASR systems, note generation against any OpenAI-compatible server, LoRA fine-tuning, a claim-level verifier with an injected-error benchmark, scorers modelled on Abridge's evaluation whitepaper, an overnight autoresearch loop, an expert-iteration (RL) exercise, and a live demo UI. See [[deliverables]].

**The one-paragraph result.** On 57 mock GP consultations ([[datasets]]), a vanilla pipeline (streaming transcript straight into an untuned note model) and the first two-pass design tie on note quality. The overnight search ([[autoresearch-loop]]) then found +2 to +4 composite points on held-out data by naming the speakers before note writing ([[role-mapping]]), a precision-first instruction, and a different note writer. It also optimized citations away because the score lacked a verifiability term; re-scored with one, the cited version ties the uncited on the held-out set while halving unsupported sentences ([[citations-and-verifiability]]). The finding that survived every change of data, judge and metric is that the ASR decoder, not latency, decides medical-term loss ([[decoder-finding]]). The cost of the optimized pipeline is plan completeness, half of which is the cited writer declining to guess orders the doctor never said aloud ([[plan-recall-gap]]). An expert-iteration RL exercise on the local writer transferred style (citations, brevity, grounding) but no held-out content gain, and the two judges disagreed on its sign ([[expert-iteration]]).

**How to read the rest.** Findings pages carry a **transferred / candidate** tag ([[benchmark-maxing-vs-quality]]). Every number has a split, a judge and a source file. The head-to-head is in [[vanilla-vs-best]]; the spoken version is in [[interview-narrative]].
